写一个 C++ MCP SDK 时，我真正关心的几件事

协议 SDK 的难点通常不在“能不能发 JSON”，而在你能不能把协议边界变成稳定、可验证、可组合的工程接口。

我做 cxxmcp 的出发点很直接： C++ 侧需要一个不只停留在 demo 层的 Model Context Protocol SDK。它应该能写 server， 也能写 client；能跑通示例，也能承受下游项目的验证。

第一件事是生命周期

MCP 看起来是请求、响应、通知，但 SDK 真正要处理的是连接生命周期、初始化顺序、资源释放和异常路径。 如果生命周期没有被建模清楚，用户就会在“看似能跑”的基础上写出难以定位的状态错误。

第二件事是错误语义

错误不是字符串。一个好的 SDK 要让调用者知道错误来自传输层、协议层、业务 handler， 还是对端能力不匹配。这样调用方才能选择重试、降级、断开连接或者直接把问题暴露出来。

第三件事是下游验证

只在库仓库里写单元测试是不够的。我更信任 application-style examples 和 conformance tests， 因为它们会逼着 API 暴露真实使用姿势里的不顺手。SDK 的设计质量，最终要由使用它的项目来证明。

这也是我把 cxxmcp-examples 和网关、运行时管理工具放到一起推进的原因：协议库只有接触真实运行环境，才会长出正确的形状。
