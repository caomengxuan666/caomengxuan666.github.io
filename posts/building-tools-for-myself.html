为什么我喜欢给自己写工具

一个小工具如果每天能少打几次断点、少翻几次文档、少忍几次环境差异，它就已经赚回来了。

我喜欢写工具，不是因为工具本身复杂，而是因为它们诚实地暴露工程里的摩擦。 命令不顺手、平台行为不一致、依赖复制粘贴、重复配置，这些问题单独看都很小， 但每天遇到就会变成真实成本。

WinuxCmd：把习惯带到 Windows

WinuxCmd 的目标很朴素： 在 Windows 上提供轻量、原生的 Linux 命令实现。它不试图变成完整发行版， 而是解决“我现在就想用熟悉命令处理文件”的那一类问题。

CMakeHub：少复制，少漂移

CMake 项目里经常会出现散落的模块、复制来的片段和隐式依赖。 CMakeHub 更像是把这些片段收束成一个可以浏览、使用、缓存和检测冲突的入口。

工具是个人工程系统的一部分

给自己写工具的收益会复利。第一次只是省十分钟，第二次开始形成固定工作流， 第三次你会发现它影响了你设计其他项目的方式。好的工具会反过来训练工程习惯。
